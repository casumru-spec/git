# Конспект по Git и Git Flow

## 5 основных тезисов про Git
1. **Локальность и скорость:** Git хранит всю историю проекта локально в скрытой папке `.git`, поэтому создавать коммиты и переключаться между ветками можно без доступа к интернету.
2. **Три зоны работы:** Изменения проходят путь от рабочей директории через область подготовки (`git add`) в историю репозитория (`git commit`), что позволяет формировать чистые и осмысленные снимки.
3. **Снимки состояния:** Каждый коммит фиксирует состояние проекта в конкретный момент времени и отвечает на вопрос «зачем внесены изменения».
4. **Безопасные эксперименты:** Ветки работают как лёгкие указатели на коммиты, позволяя разрабатывать новые функции изолированно от основного рабочего кода.
5. **Синхронизация с сервером:** Удалённый репозиторий (`origin`) служит для обмена кодом между участниками команды через команды `push`, `pull` и `fetch`.

## 5 основных тезисов про Git Flow
1. **Разделение стабильного и нового кода:** Ветка `main` хранит только проверенные релизы, а вся текущая интеграция задач происходит в ветке `develop`.
2. **Изоляция задач:** Каждая новая функция разрабатывается в отдельной ветке `feature/*`, которая ответвляется строго от `develop` и вливается обратно только через Pull Request.
3. **Защита основных веток:** Разработчики не отправляют изменения напрямую в `main` и `develop`, что исключает случайную поломку проекта.
4. **Подготовка релиза:** Перед выпуском версии создаётся ветка `release/*` от `develop`, где исправляются только мелкие ошибки перед вливанием в `main` и обратно в `develop`.
5. **Экстренные исправления:** Критические ошибки на продакшене чинятся в ветке `hotfix/*` от `main`, после чего изменения обязательно переносятся и в `main`, и в `develop`.

## Таблица веток Git Flow

| Ветка | Откуда создаём | Куда вливаем | Зачем нужна |
| :--- | :--- | :--- | :--- |
| **`main`** | Инициализируется при старте проекта | Сюда вливаются только `release/*` и `hotfix/*` | Хранит стабильный, готовый к продакшену код и релизные теги |
| **`develop`** | От `main` при старте проекта | Сюда вливаются `feature/*`, `release/*` и `hotfix/*` | Основная ветка интеграции для сборки следующего релиза |
| **`feature/*`** | Только от `develop` | Только в `develop` (через PR) | Изолированная разработка новой функциональности или задачи |
| **`release/*`** | От `develop` | В `main` и обратно в `develop` | Финальное тестирование, исправление багов релиза и подготовка версии |
| **`hotfix/*`** | Только от `main` | В `main` и в `develop` | Срочное исправление критических ошибок в уже выпущенной версии |
